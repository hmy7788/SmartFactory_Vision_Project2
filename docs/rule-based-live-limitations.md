# 라이브 검사 룰베이스(`--model-type rule_based`) 한계 정리

`scripts/live_inspection.py --model-type rule_based`는 학습된 검출 모델(RT-DETR/YOLO) 없이
`src/vision/rule_based_adapter.py`가 classical CV(색상 + 구멍 개수)만으로 개별 부품을 찾아
`InspectionService`에 넣는 방식이다. 이 문서는 그 구조적 한계를 정리한다.

## 동작 방식 (요약)

1. 검은 배경 위 전경 덩어리를 전부 찾는다 (`find_all_blobs`, Otsu+`RETR_CCOMP`).
2. 덩어리 내부 HSV로 볼트(`bolt_1`/`bolt_2`) 색상 판정 — 여기 안 걸리면 나무막대 후보.
3. 나무막대는 **빈 구멍 개수**로 1차 분류: 5개=`mother_part`, 3개=`part_3hole`, 2개=`part_2hole`.
4. 개수가 애매하면, 같은 프레임에 `mother_part`가 있을 때만 그 길이 대비 비율로 2차 판정.
5. `cv2.minAreaRect`로 중심/장변/단변/각도를 직접 구한다.

## 핵심 한계

### 1. 볼트가 꽂히면 구멍이 개수에서 사라진다

볼트가 구멍에 완전히 밀착하면(배경이 하나도 안 남으면) 나무와 하나의 덩어리로 합쳐져서,
그 구멍은 "빈 구멍"으로도 "분리된 볼트"로도 안 잡히고 **개수 자체에서 빠진다**. 즉 볼트가
꽂힐수록 인식되는 구멍 개수가 줄어든다.

### 2. 줄어든 개수가 우연히 다른 클래스와 같아지면 오분류된다 (못 고치는 문제)

2차 보정(길이 비율)은 "정확히 일치하는 클래스가 없을 때만" 시도된다. 그런데 줄어든 개수가
**우연히 다른 클래스의 정상 개수와 같아지면**, "정확히 일치"로 먼저 처리돼버려서 길이 보정까지
가지도 못한다.

- 예: `part_3hole`(구멍 3개)에 볼트가 1개 꽂히면 빈 구멍이 2개 남는데, 이건 `part_2hole`의
  정상 개수(2개)와 똑같다 → mother가 화면에 있어도 `part_2hole`로 오분류된다.
- `tests/test_rule_based_adapter.py::test_coincidental_hole_count_is_a_known_misclassification`에서
  이 시나리오를 그대로 재현해 오분류가 실제로 일어남을 확인해 뒀다 (회귀 방지용 — "고쳐지면
  실패하는" 테스트가 아니라 "이 한계가 여전히 존재함"을 잠그는 테스트).
- 구조적 문제라 이 어댑터(구멍 개수 기반) 설계로는 해결이 안 된다. 해결하려면 "몇 번째
  구멍에 볼트가 있는지"까지 보는 위치 기반 판정(=`hole_count_check.py`의 최종 형태 검증
  로직)이 필요한데, 그건 완성된 단일 조립체를 전제로 하지 실시간 멀티 오브젝트 검출과는
  전제가 다르다.

### 3. 부품끼리 맞닿거나 겹치면 분리가 안 된다

볼트 유무와 무관하게, 두 물체 사이에 검은 배경(틈)이 하나도 안 남으면 하나의 덩어리로
합쳐져서 각각 따로 인식할 수 없다. 조립이 진행돼 부품들이 서로 밀착할수록 이 문제가 커진다
— 완성된 조립체(모든 부품이 맞닿은 상태)는 사실상 하나의 큰 덩어리 하나로만 잡힌다.

### 4. 프레임 간 추적이 없다

매 프레임을 독립적으로 처음부터 분석한다. 한 번 확실히 분류됐던 부품도 다음 프레임에
손 등으로 가려 구멍 일부만 보이면, 그 프레임만 그냥 놓친다 — RT-DETR 어댑터의 "각도 유지
(held)"처럼 이전 값을 잠깐 들고 있는 완충 장치가 없다.

## 실측 확인

- **완성된 조립체 사진** (`data/aabb/images/test/model_a_006.png` 등, 부품이 전부 맞닿은 상태):
  하나의 덩어리로만 잡히고 구멍 개수가 5/3/2 어디에도 안 맞아 **미검출**로 끝남 (한계 3번,
  오분류 대신 정직하게 빠짐 — 의도한 동작).
- **손 포함 피킹 영상 프레임** (`data/aabb/images/test/2_hole_frame*.png`): 일부 프레임에서
  실제로 클래스가 틀리게 나옴 확인함 (손 그림자/가림이 Otsu 임계값에 영향을 줌, 한계 4번과
  연결).

## 그래서 언제 쓸 만한가

| 상황 | 신뢰도 |
|---|---|
| 재료 섹션 — 부품이 서로 떨어져 있고 볼트가 안 꽂힌 상태 (오피킹 검출) | 비교적 안정적 |
| 조립 섹션 — 부품이 놓였지만 아직 볼트 전 | mother가 화면에 있으면 길이 보정으로 어느 정도 보완 |
| 조립 섹션 — 볼트가 이미 꽂힌 부품을 계속 인식 | RT-DETR/YOLO보다 확실히 떨어짐 (한계 1·2번) |
| 완성된 조립체 전체 | 이 어댑터로는 사실상 불가 (한계 3번) — `hole_count_check.py`의
  기존 "최종 형태 검증" 로직을 따로 써야 함 |

## 관련 파일

- `src/vision/rule_based_adapter.py` — 어댑터 본체, docstring에 같은 한계가 더 상세히 적혀 있음
- `src/rule_based/hole_count_check.py` — `find_all_blobs` 등 공용 컨투어 검출 로직
- `tests/test_rule_based_adapter.py` — 정상 분류 케이스 + 위 한계들을 실제로 재현하는 테스트
- `docs/live-inspection-usage.md` §5-1 — `--model-type` 비교표
