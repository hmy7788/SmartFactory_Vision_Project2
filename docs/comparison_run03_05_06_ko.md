# eval_vid 과정 검증 — 3개 모델 비교 (run03 · run05 · run06)

## 1. 핵심 결론

동일한 평가 영상(eval_vid.mp4, recipe_1)과 **동일한 설정·동일한 정답(revision 2)** 에 대해 검출 모델·실행 장치만 바꿔 세 번 평가했다.

| | run03 | run05 | run06 |
|---|---|---|---|
| 모델 | YOLO-OBB | RT-DETR | YOLO-OBB |
| 가중치 | `yolo26_obb_parts_50.pt` (5.7MB) | `best.pt` (66.3MB) | `yolo_obb_parts.pt` (5.6MB) |
| 장치 | CPU | CPU | **GPU** |

- **오류 검출**: run03·run05는 7개 사건 모두 검출·원인 일치(7/7). **run06은 A04(H4→H5 위치오류)를 놓쳐 6/7.**
- **정확도**: RT-DETR(run05)이 표시 상태 일치율 57.8% / 후보 68% / 완성품 정확도 33.6%로 세 모델 중 가장 높다. 두 YOLO-OBB는 표시 51~52%대.
- **속도**: GPU YOLO-OBB(run06)가 **25.5 FPS(p95 39.6ms)** 로 압도적. CPU YOLO-OBB(run03) 14.2 FPS, CPU RT-DETR(run05)은 **2.3 FPS**로 실시간 부적합.
- **⚠️ 세 모델 공통 문제**: **완성된 정상 조립품을 NG로 오판(false NG)** 하는 시간이 60초 중 **19~23초**나 된다. 안전측(false PASS)은 셋 다 0초지만, 정상품 오경보가 이번 라운드의 최대 약점이다.

**한 줄 정리**: 정확도는 RT-DETR, 속도는 GPU YOLO-OBB, 그러나 **세 모델 모두 완성품 오경보(false NG)라는 공통 결함**이 있어 모델 선택보다 이 문제 해결이 우선이다.

이 결과는 단일 영상에 대한 **시스템 수준 과정 평가**이며 모델 mAP·일반화·실시간 지연 보장을 의미하지 않는다.

## 4. 처리 성능

![처리 성능·처리율](charts3/02_speed.png)

- **GPU YOLO-OBB(run06)** 가 25.5 FPS로 가장 빠르고, p95가 39.6ms로 지연 편차도 가장 작다(가장 안정적).
- **CPU YOLO-OBB(run03)** 는 14.2 FPS로 실시간 경계선.
- **CPU RT-DETR(run05)** 는 2.3 FPS(평균 434ms)로 실시간 부적합 — RT-DETR의 정확도 이득을 쓰려면 GPU가 필수다.
- 측정 범위는 프레임 읽기~검출~검사~HUD이며 로그·인코딩·출력은 제외한다. **오프라인 처리 성능이지 카메라→경고 실시간 지연이 아니다.**

## 6. 정상 완성품 60초 강건성 (S29) — 최대 공통 결함

![완성품 60초 강건성](charts3/04_robustness.png)

완성된 **정상 조립품**을 60초 유지하는 구간의 표시 상태 분포다. **여기서 NG는 전부 오경보(false NG)** 다.

| 표시 상태 | run03 | run05 | run06 |
|---|---:|---:|---:|
| PASS(정상) | 12.8초 | **20.2초** | 19.8초 |
| HOLD(보류) | 25.8초 | 20.2초 | 17.5초 |
| **NG(오경보)** | 21.2초 | **19.4초** | 22.6초 |
| IN_PROGRESS | 0.2초 | 0.2초 | 0.0초 |

- 세 모델 모두 완성품을 **PASS로 유지하는 시간이 절반도 안 되고(21~34%)**, 나머지는 HOLD(연결 불확실)와 **NG 오경보**로 샌다.
- RT-DETR(run05)이 PASS 유지 20.2초로 가장 낫지만 여전히 NG 오경보 19.4초.
- 이전 라운드(run01/02)에서는 이 구간의 NG 오경보가 0이었다. **이번 라운드 세 모델 모두 완성품 false NG가 새로 나타난 점**은 모델 문제가 아니라 공통 파이프라인/기하·판정 로직 변화일 가능성이 높아 우선 조사 대상이다.

## 7. 안전성 — 오경보(false NG) vs 놓침(false PASS)

![오경보·false PASS](charts3/05_safety.png)

- **false PASS = 0초 (세 모델 공통)**: 미완성·오류를 PASS로 오판하지는 않는다 → 안전측 실패는 없다.
- **false NG = 19~23초**: 반대로 정상품을 NG로 막는 오경보가 크다. 현장에서는 정상 작업을 반복 차단해 **작업 흐름을 방해**하는 유형이다. run05의 오경보 시간이 가장 짧지만(19.4초) 에피소드는 8건으로 잦고, run03은 시간 21.2초이나 에피소드 4건으로 덜 잦다.

## 8. 종합 판단

| 관점 | 권장 |
|---|---|
| 검출 신뢰도(사건 7/7) | **run03(yolo26)** 또는 run05. run06은 A04 미검출로 제외 |
| 정확도 최우선 | **run05(RT-DETR)** — 단, CPU 2.3 FPS라 GPU 필수 |
| 실시간·속도 | **run06(GPU YOLO-OBB)** 25.5 FPS, 그러나 검출 신뢰도 낮음 |
| 균형(정확도+속도+신뢰도) | **run03**을 GPU로 돌리는 구성 검토 — yolo26은 검출이 가장 견실하고 GPU면 속도도 확보 가능 |

- **모델만 놓고 보면**: 검출 견실성은 `yolo26`(run03) > `best.pt`(run05) > `yolo_obb_parts`(run06). 정확도는 RT-DETR이 최고이나 GPU 없이는 실시간 불가.
- **가장 시급한 것은 모델 교체가 아니다**: 세 모델 공통으로 완성품 false NG(19~23초)와 HOLD가 크다. 이는 association/기하·판정 안정화 문제이므로, 이 파이프라인 결함을 먼저 잡아야 어떤 모델을 쓰든 완성품 판정이 안정된다.

## 9. 한계

- 단일 영상·사건 7건에 대한 **시스템 수준 과정 평가**다. 모델 mAP·일반화 성능이 아니다.
- 오프라인 처리 FPS는 실시간 카메라→경고 지연이 아니다.
- run06의 장치는 GPU(device 0), run03·run05는 CPU라 **속도 비교에는 장치 차이가 섞여 있다**(모델 단독 속도 비교가 아님).
- false NG/false PASS는 정답 상태가 명시된 구간 기준이며, 최초 오류 관찰 시점은 라벨링되지 않아 감지 지연은 산출하지 않았다.
- 본 비교를 위해 코드·threshold·채점 기준을 변경하지 않았다.
