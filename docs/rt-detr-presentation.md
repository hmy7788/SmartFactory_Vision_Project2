# RT-DETR 실험 발표 정리

> 상세 로그는 `docs/rt-detr-experiment.md` 참고. 이 문서는 발표/노션 정리용 요약본.

---

## 1. 목적

CLAUDE.md 3-1에서 메인 파이프라인은 **YOLO-OBB**로 확정돼 있지만, "RT-DETR도 비교 후보로 고려 가능"이라는 조항에 따라 `experiment/rt-detr` 브랜치에서 별도로 검증했다.

- 확정 사항이 아니라 **비교 실험**이라는 점이 핵심
- RT-DETR은 OBB(회전 박스)를 지원하지 않아서 **AABB로 변환**해서 학습 (YOLO-OBB 대비 불리한 조건)

---

## 2. 데이터셋 — 3차에 걸쳐 확장

| 실험 | 데이터 구성 | 총 장수 |
|---|---|---|
| 1차 | ICONIC(부품 1개짜리 정적 촬영)만 | 500장 |
| 2차 | 1차 + 완성 조립체(Model A/B/C) 사진 | 659장 |
| **3차(최종)** | 2차 + 픽킹 영상(손 포함) + 조립 진행중 프레임 | **980장** |

**3차에서 새로 합친 데이터(`data/labeled_data`) 정리 과정에서 발견/보완한 점:**

- 팀원이 넘겨준 라벨 중 **클래스 ID가 프로젝트 표준과 반대로 매겨져 있던 것**을 발견 (bolt_1/bolt_2, part_2hole/part_3hole 순서 반전) → 재매핑 스크립트(`merge_labeled_data.py`)로 교정
- 서로 다른 두 폴더(`train`/`train2`)에 **같은 사진 100장이 완전 중복**으로 들어있던 것을 md5 해시로 자동 감지·제거 (`prepare_rtdetr_dataset.py`) — 그대로 합쳤으면 같은 사진이 train/val 양쪽에 새어 들어가는 데이터 누수 발생할 뻔함
- 최종적으로 **같은 데이터를 AABB(`data/aabb`)/OBB(`data/obb`) 두 버전으로 동시 생성** — 나중에 YOLO-OBB와 공정 비교 가능하도록 seed 고정, 동일 train/test 분할(831/149장)

## 5. 실험을 거치며 보완한 문제들 (타임라인)

1. **1차 실험**: ICONIC만 학습 → `part_2hole`/`part_3hole`을 같은 박스에서 동시에 오탐지(클래스 혼동) 발견
2. **2차 실험**: 완성 조립체 사진(비슷한 부품이 나란히 등장) 추가 학습 → 클래스 혼동 문제 해결 확인
3. **3차 실험**: 손 포함 픽킹 영상 + 조립 진행중 프레임까지 합쳐서 실전 환경(손 가림, 다양한 각도)에 더 강건하게 확장, val셋 149장 전체 검증까지 완료

## 부록: 관련 산출물 (룰베이스 조립 검증, 참고용)

RT-DETR과는 별개 트랙이지만 같은 데이터(`data/aabb`)를 기반으로, CLAUDE.md 3-2 "룰베이스(필수)" 요구사항에 맞춰 **구멍 개수 + 위치 + 볼트 색으로 Model A/B/C를 판별하는 순수 컨투어 기반 알고리즘**(`src/rule_based/hole_count_check.py`)도 함께 개발함 — 색상 의존 없이 100장 기준 100% 정확도(위치/색 검증 추가 후 97%) 달성. 필요하면 별도로 정리 가능.
